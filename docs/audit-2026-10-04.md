## 1. Data-loss chain (fix first — a few lines each)

1. ✓ `build_all.sh:219-242` — exit status is always 0, even with failures. `tribonian build && tribonian sync-vault` syncs a broken build. Fix: last line `exit $(( $(grep -c '^FAIL' "$log") > 0 ))`.

3. ✓ `sync_remarkable.py:69,119` — any byte change → `rmapi put --force`, which replaces the tablet document and drops pen annotations. pdflatex embeds timestamps, so `FORCE=1 tribonian build` changes every hash and the next sync force-overwrites every annotated PDF. 4. ✓ `casedb.py:166-172` — `load opinions --limit N` still runs `DROP TABLE IF EXISTS opinions` on the 64 GB opinions database. Fix: load samples into `<table>_sample` or a separate file.

6. `build_all.sh:43-45` + `sync_remarkable.py:27` — durable state (`built.tsv`, `stamps/`, `rm_manifest.json`) lives in the scratch dir `build/`. `rm -rf build` forces a full rebuild and resets the tablet manifest (then item 3 bites). Fix: move to `state/`.

## 3. Statistics and benchmark — claims are softer than the docs say

19. ✓ `cocite.py:1880` — the "consensus" partition is `parts[0]`: the first run of the last round. If the loop exits by round exhaustion rather than `undecided < 0.01`, one disagreeing run is picked arbitrarily. Also later rounds switch to plain modularity at resolution 1 (`:1871`) even under `--method cpm --resolution 0.5`. Fix: final partition = connected components of the ≥ τ consensus graph (the actual Lancichinetti–Fortunato step), same objective every round.
20. `cocite.py:1825-1842, 1999-2013` — the reported F1 0.914 / precision 1.000 is best-of-grid on 65 gold names, and pairwise F1 is computed only over gold-labelled lineages. An area that swallows 2,000 unlabelled lineages while keeping the 65 gold ones grouped scores precision 1.0. Gold labels are themselves outputs of the clusterings being compared (re-attached by fingerprint Jaccard ≥ 0.3). Fix: pre-register one cell before the view comparison; add area-size / non-gold-fraction to the report.
21. `casemap.py:234` vs ARCHITECTURE §7.3 — casemap says R9 was tuned on all 40 overruled + 20 controls; ARCHITECTURE calls set B a check set. One of them is wrong; the README (line 108) already half-admits B was looked at. Pick one statement.
22. `cocite.py:458-473,561-562,601` — sub-cluster split test is a z-score from 5 null draws (3 at slice level) with a 1e-4 sd floor. sd from n=5 has ~35% relative error; when nulls agree by chance, anything passes "4 sd". Fix: empirical one-sided test with ≥ 20 nulls, or a fixed margin.
23. `cocite_shift.py:85-93` vs `:254` — collapse cohort decade comes from citing-side years (0 for cases with no outgoing edges, so they're silently excluded), A's decade from clusters. Fix: both from `clusters.date_filed`.
24. `cocite.py:953-959,1117` — under `NOTE_VIEW` (`--mix 0.2`) `partners.support` holds `0.2·support + 0.8·sentence`, stored as INTEGER, but the note text calls it "decisions citing both". Lift/cosine are also on the mixed weight.
25. `cocite.py:868,987,1395,2271` — "newest complete slice" uses the wall clock, not the bulk dump date (four copies).
26. `casemap.py:1045-1058` — citedby prints "(±5% at 95%)" for the designed n over Np, but percentages are over the linked subset na. Print the achieved half-width.
27. `goodlaw_eval.py:77-79` and cocite read paths (`cocite.py:762,1621,1686,1725`, `cocite_shift.py:49`) — caches never checked against the bulk-load stamp; only `cmd_build` passes `stamp`. After a new dump, old view DBs silently combine with new cache arrays.
